# Hermes WebUI 性能排查与优化记录

针对第三方 npm 包 [`hermes-web-ui` / Ekko Studio](https://github.com/EKKOLearnAI/ekko-studio) 的一次可复核性能排查：从本机静态文件也慢，追踪到 **LAN discovery 广播进入 TUN 转发循环、Node 主线程重复枚举网卡**；再处理重复下载的大图标、重复初始化请求和冷启动依赖瀑布。

不是 Nous Research Hermes Agent 官方 Dashboard 的补丁，不是上游官方项目，也不是适用于所有安装环境的一键加速器。

| 部分 | 状态 |
|---|---|
| `0.7.22` 问题诊断与分阶段优化 | 已在一个真实自托管环境验证 |
| 同源、相同鉴权/profile 的在飞 GET 合并 | 有实现、隔离与竞态回归测试 |

## 现象

- 本机 loopback 访问入口 JS，耗时也约1.95秒，排除“只是公网慢”。
- Node 进程接近占满一个核心，但整机CPU仍有大量空闲。
- 数秒内捕获上万条同一个 discovery request ID；CPU栈集中在UDP回调中的`os.networkInterfaces()`。
- 登录后刷新仍下载约7.31MB资源正文：原尺寸PNG占5.30MB，用户/profile响应主要是头像字符串。
- 公网连接和FRP也存在独立波动，曾发生502，不能归结为单一原因。

## 措施与收益

```text
分层测量
  ├─ loopback vs 公网 → 不是只有公网慢
  ├─ CPU + syscall + perf → UDP处理里的网卡枚举
  ├─ 抓包 + 带mark查路由 → 广播先命中local表，绕过预期防环分流
  └─ 登录态 resource timing → 大图、重复GET、模块串行发现

最小干预
  ├─ 只drop已证实异常的TUN广播目的地址 + UDP发现端口
  ├─ 原尺寸图标缩为适合显示的256px图片，保留原图备份
  ├─ 合并同源、同URL/请求头/选项的在飞GET，不保留完成缓存
  └─ 仅聊天路由提前准备原本就要下载的模块与Markdown
```

### 0.7.22 实测快照

相同测试主机、桌面Chrome、已登录当前会话；“完整首屏”包含侧栏、消息正文Markdown、输入框、可视图片、背景解码。不是`window.load`，不是只显示空框。

| 场景 | 最初基线 | 全部0.7.22优化后的最后一轮 |
|---|---:|---:|
| 本机冷加载 | 10.925s | 2.093s |
| 本机普通刷新 | 3.568s | 1.253s |
| 公网冷加载 | 14.939s | 5.767s |
| 公网普通刷新 | 6.801s | 2.139s |

其他成功样本中，公网刷新也出现 **6.910s**。上表是快照，不是P95，也不是“每次都能秒开”的承诺。

- 断环后Node单核CPU：约99% → 最初4.67%，稍后一次采样0.67%。
- 本机入口JS下载：约1.95s → 0.037s。
- 五次图标请求累计：5,303,531 → 292,771字节。
- 刷新资源正文：7,314,649 → 1,409,086字节。
- `profiles`：冷3次/热2次 → 每轮1次；`auth/me`：2次 → 1次。

## 使用

Python 3.10+；Node.js 22+（仅运行JS测试）。Python工具只用标准库，图标转换示例另需Pillow。

```bash
git clone https://github.com/Yunxi-Yaoyao/hermes-webui-performance-notes.git
cd hermes-webui-performance-notes
python3 -m unittest discover -s tests -p 'test_*.py' -v
node tests/test_singleflight.cjs patches/singleflight.js
```

先读[排查步骤](docs/diagnosis.md)，确认是同一问题；再看[操作与回滚](docs/usage.md)。

### 只预览网络规则

以下使用文档示例地址，**不是推荐直接用于任何主机**：

```bash
python3 scripts/discovery_guard.py --action show \
  --interface tun-test --subnet 198.51.100.0/30 --port 52008
```

只有确认真实TUN地址、广播目的地址和循环端口后，才能替换参数并显式`apply --confirm`。它不修上游发现算法，不自动创建开机任务、不停止整个代理。

### 检查前端补丁支持情况

```bash
python3 scripts/frontend_overlay.py check \
  --root /path/to/hermes-web-ui \
  --backup-dir /path/outside-package/webui-overlay-backup
```

无补丁/未知版本应返回非零状态，不能当作网站故障。安装器只管理GET合并脚本；图标与预加载单独说明，**单独安装脚本不保证获得案例中的全部收益**。

## 更新兼容原则

1. 不固定阻止上游升级，不自动降级。
2. 不重写上游带hash的JS，不把旧index整页覆盖到新版。
3. 版本号与主文件摘要都匹配才允许修改；未知新版零修改、明确报错。
4. 升级覆盖优化很正常，必须重新检查；内置CLI restart不保证经过systemd钩子。
5. 新版登录成功 ≠ 旧补丁自动兼容；新版本支持需要新的实测与回归。

详见[升级与兼容边界](docs/compatibility.md)。

## 限制

这是单环境案例，不是大规模基准。网络波动、执行期负载和会话增长影响绝对耗时。规则只处理已确认的特定循环，不能照搬到其他拓扑。公网完整首屏稳定1秒尚未达成；剩余大头是头像API与会话初始化/公网等待。
