# 测量结果及其边界

采集日期：2026-09-24。Linux自托管WebUI，桌面Chrome 1440×1000，登录后当前会话。测试期间会话持续增长，并存在公网连接波动。这里的local是服务器本机loopback，不是手机Wi-Fi实测；public是该服务器访问公网入口，不等于其他地区或移动网络。

公开数据只保留聚合值：[`data/measurements.json`](../data/measurements.json)。原始计时、截图、包和会话状态留在私有环境，避免泄漏消息/凭证/网络拓扑。

## 0.7.22就绪判据

导航起点到侧栏、非disabled输入框、消息气泡、Markdown正文均出现，可视图片完成且有效，主题背景blob decode完成、字体加载完成。每100ms检查，因此不是亚毫秒精确指标。HTTP安静2秒只作额外确认，不计入表内首屏时间。

冷上下文导入登录状态，不预热HTTP缓存；热用page.reload。依赖CacheStorage的背景在热刷新不一定重新fetch。当前页面正在输出，运行中状态不是页面未就绪。

## 升级检查为何单独列

0.7.24的升级验收使用较轻量探针：检测侧栏/正文/输入框、可视图片有效、背景CSS变量含blob URL；没有显式decode、字体等待。表内ready_s由测试脚本墙钟计算，和旧版页面内performance.now采样口径有差别。

旧前端改动未重放；独立TUN guard保留。新版运行正常和两次成功加载足以支持“升级主要功能验收通过”，不支持“上游修了某个缺陷”或“新版比优化后的旧版必定更快”。

## 安全与失败样本

- 捕获过公网502、连接超时；单独归档，不当作成功样本，更没有拿其无穷大耗时计算夸张提升比例。
- 测试过错的热加载goto及缓存背景判据，相关无效数据未混入最终值。
- strace/perf会增加开销；正式网页计时不与这些附加采样同时运行。
- 独立浏览器首次出现版本公告弹窗；首屏呈现不包含用户点击关闭弹窗的时间。
- 测试未验证发送新聊天消息，避免产生付费生成或修改对话内容；真实用户此后在同一会话正常继续交流提供了额外运行证据，但不是全功能测试套件。

## 下一步更严格的比较

固定同一个不再增长的测试会话、同设备、网络、viewport；交替A/B，每组更多样本，保留失败率和P50/P95；分别记录UI-shell、session-list、WS resumed、Markdown和图片就绪。变更前后应同时比较CPU与字节量，不只拿一次截图或curl首页200当性能验收。
